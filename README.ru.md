**ИИ-агент для программирования, работающий локально: одна среда выполнения на твоей машине, с любой моделью, совместимой с OpenAI.**

DeepSeekCode запускается на собственной машине и открывает одно и то же ядро агента через несколько интерфейсов: интерактивный TUI, веб-рабочее пространство на `http://localhost:8080`, HTTP/WebSocket API и пакетный режим JSONL для CI. Каждый вызов инструмента проходит через слой разрешений, которым управляешь ты, а интерфейс переведён на 12 языков.

Этот репозиторий — **точка публичной раздачи**: страница загрузки (GitHub Pages) и установщики для десктопа. Репозиторий с исходным кодом закрыт.

## Ключевые возможности

- **Одна среда выполнения, несколько интерфейсов** — TUI в терминале, веб-интерфейс, HTTP + WebSocket API и `dscode exec` с JSONL для скриптов и CI. Отдельный бэкенд ставить не нужно.
- **Слой разрешений на каждом вызове инструмента** — области `system > project > user > local > session` (побеждает самая узкая), политики `auto` / `ask` / `deny`, необязательный ИИ-классификатор для серой зоны, и таймаут означает отказ.
- **Строго режим плана только для чтения** — `/plan` выдаёт чек-лист; ничего не выполняется до твоего утверждения, а работающий цикл подхватывает этот чек-лист, а не переключает движок.
- **Переключаемые на ходу режимы** — `act`, `auto-act`, `goal`, `auto-goal`, `chat` (`Shift+Tab` перебирает их).
- **Около 70 встроенных инструментов** — файлы, поиск, git, LSP, анализ кода, браузер, субагенты, планы, память, MCP.
- **Инструменты оболочки в песочнице** — bwrap в Linux, SBPL в macOS, MXC / Docker в Windows; если подходящей политики нет, он отказывается выполнять команду, а не откатывается к оболочке хоста без песочницы.
- **Расширяемость** — серверы MCP, навыки, плагины, субагенты, фоновая работа, воркфлоу и каналы мессенджеров (LINE, Slack, WhatsApp, QQ, DingTalk, Feishu) с проверкой подписи входящих запросов.
- **Устойчивость** — память, переживающая сессии, и необязательный сторож, способный продолжить запуск, прерванный по причине, отличной от явной остановки пользователем.
- **Темы** — dark, light, nord, dracula, monokai, one-dark, tokyo-night.

## Установка

### npm (Node.js >= 18)

```bash
npm install -g @deepseekcode/cli
dscode
```

Устанавливаются две команды: `dscode` и `deepseekcode`.

### Установщики для десктопа

| Платформа | Форматы |
| --- | --- |
| Windows x64 | `.exe` (NSIS), `.msi` |
| macOS (Apple Silicon + Intel) | универсальный `.dmg` |
| Linux x64 | `.deb`, `.rpm`, `.AppImage` |

Скачивать в [Releases](https://github.com/deepseekcode/deepseekwork/releases). К каждому файлу прилагается одноимённая подпись `.sig`.

## Первый запуск

1. Запусти `dscode` — ядро агента и сервер HTTP/WebSocket стартуют в одном процессе.
2. Открой `http://localhost:8080/#models` и настрой endpoint, совместимый с OpenAI. Подойдёт любой сервер, говорящий на этом API, включая запущенный на `localhost`.
3. Вернись в терминал и опиши задачу. Всё, что пишет файлы или выполняет команды, проходит через слой разрешений.

## Скрипты и CI

```bash
dscode exec "fix the failing test in src/utils"   # одна задача, вывод в JSONL
dscode exec --file ./task.txt --text              # задача из файла, вывод обычным текстом
```

`exec` выводит по одному JSON-объекту на строку, поэтому результат удобно обрабатывать программно; stdin, не являющийся TTY, тоже включает неинтерактивный режим.

## Как поддерживается этот репозиторий

**Выпуск новой версии — без правок кода**

1. Поставь в репозитории с исходниками тег `desktop-v*`; его workflow `desktop-release` соберёт установщики для трёх платформ и загрузит их в Releases этого репозитория.
2. При загрузке страница запрашивает у GitHub `/releases/latest` самый свежий тег `desktop-v*` — бейдж версии, ссылки на скачивание и ссылка на релиз подтягиваются сами.

`CONFIG.version` и `CONFIG.cliVersion` — лишь запасные значения, они используются, когда GitHub API ограничивает запросы или пропала сеть.

**Правка самой страницы (тексты, вёрстка, структура)**

1. Правь `website/index.html` в репозитории с исходниками. Тексты лежат в словарях `EN` / `OV`: 58 статических строк на странице — это предварительно отрендеренный снимок, который `render()` перезаписывает в браузере из того же словаря, так что две стороны не расходятся.
2. Если тексты менялись, перегенерируй страницы по языкам: `node website/tools/gen-locales.mjs` (используется тот же словарь i18n; непереведённые ключи откатываются на английский).
3. Синхронизируй `website/` сюда и запушь → GitHub Pages обновится сам.

**Статистика загрузок** — GitHub отдаёт только накопительный `download_count` по каждому файлу, поэтому `release-stats.yml` раз в сутки записывает это накопленное значение в `.gh-stats/downloads.csv`; «новые загрузки за последние N дней» считаются из этого ряда: `powershell -File scripts\gh-download-stats.ps1 -Report 7`.

**Разовая настройка GitHub Pages** — Settings → Pages → Source: **GitHub Actions**. Выкладкой занимается workflow, выбирать ветку или папку не нужно.
